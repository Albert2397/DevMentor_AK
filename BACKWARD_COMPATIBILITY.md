# Kompatybilność wsteczna

Powierzchnie, które DevMentor traktuje jako **chronione kontrakty**. Skille review sprawdzają zmiany względem tego pliku; skille implementacyjne ostrzegają, gdy zmiana go łamie. Projekt nie ma jeszcze opublikowanych wersji, więc „breaking" oznacza złamanie istniejących konsumentów w repo lub danych w już wdrożonych bazach.

| Powierzchnia                                                                                               | Co jest zmianą łamiącą                                                                                                 | Wymagana ścieżka                                                                                                                                                |
| ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Publiczne API pakietów (`packages/{core,db,ui}/src/index.ts`, `register<Pakiet>`, typy `*Cradle`)          | Usunięcie lub zmiana nazwy/sygnatury eksportu, zmiana kontraktu portu w `core`                                         | Zaktualizować wszystkich konsumentów w tym samym PR; w razie potrzeby zostawić stary eksport jako `@deprecated` na jeden PR                                     |
| Wejścia `@devmentor/ui/components/*`, `lib/*`, `hooks/*`, `globals.css`                                    | Przeniesienie lub zmiana nazwy (wymagane przez CLI shadcn)                                                             | Zaktualizować importy w `app` w tym samym PR                                                                                                                    |
| Schemat bazy (`packages/db/src/migrations`)                                                                | Usunięcie/zmiana typu kolumny lub tabeli, nowa kolumna `NOT NULL` bez wartości domyślnej, edycja zastosowanej migracji | Nowa migracja MikroORM razem ze zmianą encji; podejście dwuetapowe (dodaj → zmigruj dane → usuń); plan wycofania w opisie PR; `db:migration:check` i `test:int` |
| Tabele Better Auth                                                                                         | Ręczna zmiana poza `auth:migrate`                                                                                      | Zmiana tylko przez konfigurację Better Auth i `npm run auth:migrate`                                                                                            |
| Trasy HTTP (`/api/health`, `/api/auth/[...all]`) i strony (`/sign-in`, `/sign-up`, `/account`, `/backend`) | Zmiana ścieżki, metody, kształtu odpowiedzi lub kodów statusu; usunięcie trasy                                         | Przekierowanie ze starej ścieżki lub zachowanie jej na czas migracji; opis w PR; test integracyjny                                                              |
| Rola i `Actor` (`user`/`admin`)                                                                            | Zmiana nazw ról lub semantyki uprawnień                                                                                | Migracja danych, przegląd każdego serwisu `core` korzystającego z roli, test ścieżki odmowy                                                                     |
| Konfiguracja środowiska (`packages/app/src/env.ts`, `.env.example`)                                        | Usunięcie lub zmiana nazwy/formatu zmiennej, nowa wymagana zmienna bez wartości domyślnej                              | Zaktualizować `.env.example`, CI i dokumentację; opisać w PR                                                                                                    |
| Polecenia `npm run` z `AGENTS.md`                                                                          | Zmiana nazwy lub zachowania skryptu                                                                                    | Zaktualizować `AGENTS.md`, CI (`.github/workflows/ci.yml`) i hooki husky w tym samym PR                                                                         |

Zmiana łamiąca bez wymaganej ścieżki to **blocker** w review.
